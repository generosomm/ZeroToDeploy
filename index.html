Step 2 · Build

Vibe Code Through Small, Complete Features

Do not ask AI to build the entire system. Repeat this loop for every approved feature until the MVP is complete.

RULEOne outcome, relevant context, real verification
01

Choose one outcome

Example: “Staff can approve a pending request.” Define what the user should observe when it works.

02

Give relevant context

Attach `RULES.md`, the relevant PRD and schema sections, plus only the code paths involved.

03

Ask for a plan

Have the AI inspect the repository, name assumptions, and identify the smallest vertical slice before editing.

04

Implement the slice

Include interface, validation, business rule, storage, permissions, error states, and tests when applicable.

05

Run and verify

Require the exact checks it ran. Test the success path, failure path, forbidden role, and important edge cases.

06

Record and continue

Update context and handoff notes, commit the working slice, then start the next focused session.

Prompt recipe

Context + Goal + Behavior + Limits + Done

If a prompt contains these five ingredients, the AI has fewer reasons to guess or change unrelated code.

01ContextWhich docs and files matter?
02GoalWhy does the user need it?
03BehaviorWhat happens step by step?
04LimitsWhat must remain unchanged?
05DoneWhat checks must pass?
Save tokens with context routing

Give the AI only what the current task needs

The full context kit stays in the repository. Individual sessions reference the relevant documents and code paths.

PRD.mdScope, users, behavior, and acceptance
ARCHITECTURE.mdLayers, data flow, and file placement
SCHEMA.mdData, APIs, permissions, and validation
DESIGN.mdScreens, components, states, and accessibility
RULES.mdAlways include for implementation work
Good vs. vague

Describe observable behavior, not just a feature name

Example task: add approval to a staff dashboard.

Vague
“Add an approval feature and make it work.”
  • No relevant files
  • No permissions
  • No failure behavior
  • No completion checks
Clear
“Read RULES.md, the approval requirements in PRD.md, SCHEMA.md, and the request module. Staff may approve pending requests assigned to them; clients cannot approve. Save the approver and time, prevent duplicate approval, show success and error states, and add tests for allowed, forbidden, and already-approved cases. Inspect first, propose a plan, and change only relevant files.”
  • Routes the right context
  • Defines behavior and permissions
  • Covers edge and error states
  • Requires tests and scope control
Step 3 · Structure

Use This Folder Contract for Every Project

Framework-specific filenames may change, but these responsibilities stay in familiar places. The generated prompt instructs AI to follow this structure.

iproject-root

Select a folder or file to understand its single responsibility.

Rules the AI must follow

  • Pages compose components; they do not contain every responsibility.
  • Client API calls live in `client/src/services/`.
  • Business logic lives in `server/src/services/`.
  • Roles, statuses, and fixed values live in `constants/`.
  • Every database change gets a migration and schema update.
  • Project facts stay in `context/`; session notes stay in `docs/handoffs/`.
Step 4 · Launch

Do Not Deploy Until These Gates Pass

AI can help perform the checks, but a human must verify sensitive data, permissions, backups, client acceptance, and production access.

FINISHTested release + rollback plan + client handover
Gate 01

Requirements accepted

  • MVP and non-goals approved
  • Every feature has acceptance checks
  • Roles and permissions confirmed
  • Open assumptions resolved
Gate 02

System verified

  • Success and failure paths tested
  • Forbidden access tested
  • Responsive and accessible
  • No critical errors or fake fallbacks
Gate 03

Production prepared

  • Secrets stored outside code
  • Migration and backup tested
  • Logs contain no sensitive data
  • Monitoring and rollback documented
Gate 04

Client handed over

  • Staging accepted in writing
  • Admin and user guides delivered
  • Credential ownership transferred
  • Support period and backlog recorded
Production rule

Vibe code the prototype. Review, test, secure, back up, and obtain client approval before shipping the production system.
