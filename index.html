Learn Before You Prompt

How to Talk to AI Like a Clear Project Manager

You do not need programming vocabulary. You need to explain the situation, desired behavior, limits, and what a successful result looks like.

10-minute beginner lesson
The reliable prompt formula

Context + Goal + Behavior + Limits + Done

The builder above collects these ingredients and turns them into instructions an AI coding assistant can follow.

01ContextWhat exists and which files matter?
02GoalWhy does the user need this?
03BehaviorWhat should happen step by step?
04LimitsWhat must it avoid or preserve?
05DoneHow will you verify it works?
01

Point to relevant context

Name the requirement document and code paths related to the task. Do not attach the entire project every time.

Read context/RULES.md and the login files.
02

Describe the user behavior

Tell the AI who acts, what they do, and what should happen next. Behavior is clearer than vague implementation words.

Staff approves a request; the client sees Approved.
03

Ask for a plan first

For a complex feature, let the AI inspect dependencies and propose small steps before it changes files.

Analyze first. Propose a plan. Implement step one only.
04

Give the AI a useful role

A role sets priorities. Choose the expertise the task needs, such as accessibility, security, database design, or performance.

Act as a security-conscious senior web engineer.
05

Build through small prompts

Finish and test one vertical slice before adding the next. Small sessions cost fewer tokens and are easier to undo.

Form → validation → save → test. Then stop.
Good vs. vague

Specific prompts give the AI fewer reasons to guess

Task: add a request search experience to a staff dashboard.

Vague prompt
“Add search to the dashboard and make it look good.”
  • No user or reason
  • No files or existing behavior
  • No loading, empty, or error states
  • No way to decide whether it is finished
Clear prompt
“Act as a senior frontend engineer. Read the dashboard page, request service, and DESIGN.md. Let staff search requests by reference number or client name. Results should update after a short pause, preserve the existing filters, work by keyboard, and show clear empty and error states. Add tests for matching and no-result cases. Plan first, then change only the relevant files.”
  • Names the role and relevant context
  • Explains user behavior and constraints
  • Defines important interface states
  • Includes verification and scope control
